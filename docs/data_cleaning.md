# Data Preparation & Cleaning Workflow

> All data is **synthetic**, generated by `scripts/generate_sales_data.py` (seed 42) for the fictional retailer Meridian Home & Office Co.

## 1. Pipeline

```text
generate_sales_data.py  ->  data/raw/         (source extracts, with realistic data issues)
prepare_data.py         ->  data/processed/   (clean star schema + cleaning_log.json)
build_powerbi_assets.py ->  powerbi/ + docs/  (Power Query M, TMDL measures, data dictionary)
calculate_kpis.py       ->  expected KPI values for validating the Power BI report
validate_data.py        ->  docs/validation_report.md (17 automated checks)
```

Run everything from the repository root:

```bash
pip install -r requirements.txt
python scripts/generate_sales_data.py
python scripts/prepare_data.py
python scripts/build_powerbi_assets.py
python scripts/calculate_kpis.py
python scripts/validate_data.py
```

## 3. How the synthetic data was designed

The generator simulates a business rather than drawing random rows, so that analysis has something real to find:

- **Calendar:** 2022-2025 is simulated; only 2023-2025 is exported. 2022 is used solely to set 2023 targets the way finance would.
- **Demand:** daily order counts follow company growth (+10% 2023, +10% 2024, +6.6% 2025 in order volume), monthly seasonality (Nov-Dec peak, August uplift, Jan-Feb low) and a weekday effect.
- **Regions:** demand mix drifts by region (South and West growing, Midwest declining).
- **Channels:** Online and Marketplace gain share; Retail Stores decline; B2B Wholesale carries larger baskets and contract discounts.
- **Customers:** 1,400 accounts, three segments, heavy-tailed spend (a minority of corporate accounts drive most sales), staggered acquisition dates.
- **Products:** 71 products in 4 categories / 16 subcategories, each with its own list margin. List prices and costs rise 3% a year.
- **Discounts:** probability and depth depend on channel, subcategory (furniture tables/desks are promoted hardest) and the Nov-Dec promotion window. Discounts range 0-40%.
- **Targets:** prior-year net sales by Region x Category x Channel x planned growth (+12% 2023, +11% 2024, +10% 2025), phased by the prior year's monthly profile, with small noise.

Because these behaviours are built in, findings such as seasonality or furniture discounting are *designed* signals. Variation such as the West's 2024 spike and 2025 pull-back comes from random customer behaviour, not from a scripted rule.

## 4. Data issues injected and how they were resolved

| # | Issue in the raw export | Rows affected | Cleaning rule | Why |
|---|---|---|---|---|
| 1 | Exact duplicate rows (export re-sent a batch) | 159 | Drop exact duplicates | Duplicates inflate sales and orders |
| 2 | Internal test account `C-TEST-01` | 6 | Remove lines for customer IDs starting `C-TEST` | Not real trade |
| 3 | Category casing / padding (`FURNITURE`, `electronics`, ` Furniture `) | 452 after trimming | Trim, collapse spaces, map case-insensitively to product master categories | One value per category in slicers |
| 4 | Region casing (`WEST `) | 319 | Trim + map to 4 conformed regions | Same |
| 5 | Legacy channel names (`Web Store`, `Wholesale`, `3P Marketplace`, ...) | 958 | Explicit mapping table to 4 conformed channels; unknown values fail the run | Channel slicer must have 4 values |
| 6 | Line Total exported **before** discount on some discounted lines | 40 | Recompute all financials from Quantity, Unit Price and Discount; log differences | Components are the system of record; $2,079 overstatement removed |
| 7 | Blank ship dates | 138 lines | Kept blank (not imputed); verified every blank belongs to an **Open** order placed in late Dec 2025 | Imputing would invent facts |
| 8 | Finance workbook uses `Mid-West` on some rows | 162 | Map to `Midwest` | Targets must match `DimGeography[Region]` for TREATAS |
| 9 | Text-typed numbers and dates | all | Parse US dates, strip `$` and `,`, convert `%` to fractions | Correct types |

Checks that found **no** issue but are enforced on every run (the script stops if they fail):

- Every order line references a known product, customer and city.
- Product name/category on the order agrees with the product master (0 mismatches).
- No duplicated OrderID + line number with different content.
- Ship date never precedes order date; no order after the extract date.
- Date, customer, channel and location are identical across lines of the same order.

The full, row-counted log is in `data/processed/cleaning_log.json` and `docs/validation_report.md`.

## 5. Financial rules (documented calculation order)

```text
GrossSales     = Quantity x UnitPrice                 (list price at time of sale)
DiscountAmount = round(GrossSales x DiscountPct, 2)   (discount applied BEFORE revenue)
SalesAmount    = GrossSales - DiscountAmount          (net sales = "Sales" in the report)
CostAmount     = Quantity x UnitCost                  (standard cost at time of sale)
Profit         = SalesAmount - CostAmount             (gross profit)
```

All amounts are rounded to cents, and the validation suite proves every line reconciles within half a cent.

## 6. Star schema build

| Output table | Built from | Key decisions |
|---|---|---|
| FactSales | Cleaned order lines | Surrogate keys; order date and ship date as `date` for relationships; DiscountBand added for discount analysis |
| FactSalesTarget | Finance workbook | Month start date; region and category kept as text for TREATAS; channel mapped to ChannelKey |
| DimDate | Generated calendar | Contiguous full years 2023-2025; sort-key columns for every text label |
| DimProduct | Product master | PriceBand added |
| DimCustomer | CRM + fact | FirstOrderDate, LastOrderDate, lifetime orders/sales, ValueTier and PurchaseFrequency (static rules below) |
| DimGeography | Geography reference | One row per city; Country added |
| DimSalesChannel | Conformed channel list | ChannelType grouping |

### Customer segmentation rules (static, as of 31 Dec 2025)

- **ValueTier** - customers ranked by 2023-2025 net sales: `A - Top 10%`, `B - Next 20%`, `C - Remaining 70%`; `No purchases` for CRM accounts with no orders.
- **PurchaseFrequency** - 2023-2025 order count: `One-time (1)`, `Occasional (2-3)`, `Repeat (4-9)`, `Frequent (10+)`, `No purchases`.

These are deliberately static, which is how CRM tiers usually work. Period-sensitive behaviour (repeat rate, new vs returning) is handled by dynamic DAX measures instead.

## 7. Moving to Power Query for a live client

For a client with live sources, the same rules translate directly into Power Query steps on the raw export: `Table.Distinct` (rule 1), `Table.SelectRows` (rule 2), `Text.Trim` + `Text.Proper` / a merge with a mapping table (rules 3-5, 8), and custom columns that recompute amounts (rule 6). The Python implementation is kept here because it is testable and produces the audit log.
